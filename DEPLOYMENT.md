# GitHub Pages deployment

Target repository: https://github.com/pavelsokolovan/break-the-wall-game

## One-time repository setting

Open https://github.com/pavelsokolovan/break-the-wall-game/settings/pages.
Under Build and deployment, set Source to GitHub Actions.
If repository Actions are disabled, enable them in Settings → Actions → General and allow the official actions used by the workflow.

## Files required

Copy `.github/workflows/deploy.yml` into the repository at the same path, together with the Vite game project. The project must have:

- A `package.json` with a `build` script that invokes Vite, optionally after TypeScript checks.
- A committed `package-lock.json`, generated by `npm install`, for `npm ci` and the npm cache.
- The game entry point and source files.

The workflow sets the Vite base to `/break-the-wall-game/` and publishes `dist/`. Use imports or Vite's base URL for assets; avoid hardcoded root URLs such as `/assets/ball.png`.

For a matching local production build, run:

```sh
npm ci
npm run build -- --base=/break-the-wall-game/
```

## Deployment trigger and result

Commit and push the project and workflow to `main`. Every push to `main`, including a merged pull request, triggers a build and deployment. A local commit alone does not trigger GitHub Actions.

Watch the Deploy game to GitHub Pages workflow in the repository's Actions tab. It can also be started manually with Run workflow after it exists on the default branch.

After the first successful deployment, the game will be available at:

https://pavelsokolovan.github.io/break-the-wall-game/

No personal access token or additional repository secret is required. GitHub provides the workflow token automatically.

Syntax checks, gameplay and interface tests, and the Pages production build pass. Deployment requires the GitHub Actions Pages source setting above. Browser visual and audio verification remains outstanding because the development environment has no supported browser preview tool.
